# ML audit and redesign report — 10 October 2026

Scope: why the platform forecast the USA as World Cup winner, what else was wrong, what was
built to replace it, how it was evaluated, and what it still cannot do.

Every number here was produced by code in this repository on 2026-10-10 and can be regenerated
(see [ML_PIPELINE_V3.md](ML_PIPELINE_V3.md)). Findings are marked **confirmed** (reproduced),
**likely** (strong evidence, not proven) or **unverified**.

---

## 1. Why the USA was forecast to win — confirmed

The tournament endpoint asked the model about teams by FIFA code (`BRA`, `ESP`, `ARG`); the
model's match history is keyed by name (`Brazil`, `Spain`, `Argentina`). Exactly one of the 48
teams has a code that is also its name in that history: **`USA`**.

So 47 teams were simulated as teams with no history at all, and one as a real team.

| Check | Result |
|---|---|
| Codes found in the model's history frame | 1 of 48 (`USA`) |
| Distinct predictions across all 1,128 pairings | **3** |
| USA win probability against any opponent | 47.0% |
| Any other team's win probability against any other | 34.4% |
| USA title probability, reproduced | **28.1%** — the value the UI showed |
| Same simulation with every team a blank | USA 24.5%, next team 2.5% |

Spain and Curaçao were the same team as far as the simulator could tell. The USA was not
favoured for hosting, popularity or ranking; it was the only team the model could see.

Nothing in any model was adjusted to change this result. The fix is at the boundary where the
mismatch happened, in both engines:

- **Legacy simulator (the default engine).** `TournamentSimulator._precompute_matchups` now
  translates each FIFA code to its history name before asking the predictor, and keeps codes
  everywhere else. Pairings went from 3 distinct predictions to 1,124. With the v1.0.0 model
  unchanged, 10,000 simulations now give France 11.2%, Netherlands 11.0%, USA 6.9% (third) with
  no real results, and Switzerland 12.9%, France 9.1%, Brazil 8.8% … USA 3.8% (tenth) with the
  stored real results. The USA is no longer the only visible team; what remains is the v1.0.0
  model's own quality (section 6), which was not touched.
- **V3.** One resolver (`ForecastService.resolve`) accepts a FIFA code, the reference name, the
  display name the UI shows or the source dataset's spelling, and returns nothing for anything
  else — which the API turns into a 422, never a default team.

Verified for all 48 teams: code, reference name, UI display name and prediction-form name reach
the same team in both engines; every team has history in both (V3: 235–1,000+ matches each;
v1.0.0: as few as 3 rows for Cabo Verde, Congo DR and Curaçao). Two display names differ from
the reference — "Korea Republic" and "Bosnia & Herzegovina" — and both resolve. Tests:
`tests/test_simulator_team_identity.py` (legacy) and the identity tests in `tests/test_v3_api.py`.

## 3. What was built

A separate package, `backend/app/ml/v3`, beside the existing models. Design choices and the
reason for each:

| Choice | Reason |
|---|---|
| Train on all internationals (49,945 matches), not World Cup matches only | 1,068 World Cup matches cannot support a model; team strength is revealed in qualifiers and continental finals too |
| One chronological engine produces every feature, for training and serving | removes train/serve skew and makes leakage a structural impossibility rather than a convention: a match's features are read before its result is applied |
| Elo with importance-weighted K, margin multiplier and home advantage | the established baseline for international football; cheap, transparent, hard to beat |
| Online attack/defence ratings feeding a Poisson score model with the Dixon–Coles low-score correction | gives a full scoreline distribution, which a tournament simulator needs |
| XGBoost on the same 14 features, trained on both team orientations and averaged over them | non-linear interactions (mismatch size, competition tier) with order-invariance guaranteed |
| Equal-weight blend, temperature scaling | fitted weights and richer calibrators did not beat the simple versions out of sample (section 5) |
| Shoot-out as a logistic function of the Elo gap | fitted on 533 shoot-outs: the higher-rated side wins 55%; significant, small |
| Official 2026 bracket, head-to-head tie-breaks, Annex C third-place table | taken from the tournament regulations, verified by replaying the real tournament |

Literature this draws on: Maher (1982) and Dixon & Coles (1997) for Poisson score models and
the low-score correction; the World Football Elo method (eloratings.net) for K-factors, margin
multiplier and the 100-point home advantage; Hvattum & Arntzen (2010) for Elo as a football
forecasting baseline; Constantinou & Fenton (2012) for the ranked probability score; Guo et al.
(2017) for temperature scaling; Groll et al. (2019) for combining ratings with tree ensembles
in World Cup forecasting; Lundberg et al. (2020) for TreeSHAP; FIFA's World Cup 26 regulations
for the format. The rating parameters were not taken on trust: a search over K scale, home
advantage and margin use on development folds selected the standard values.

## 4. Data quality and leakage

Source: `martj42/international_results`, CC0, commit `b7a3a8ee…`, downloaded 2026-10-10 with
your approval. Contains the complete 2026 World Cup (Spain 1–0 Argentina in the final).

| Check | Result |
|---|---|
| Rows in / kept | 49,945 / 49,945 |
| Invalid dates, missing or negative scores, self-matches | 0 |
| Duplicate fixture on one day | 1, legitimate, kept |
| Scores above 20 goals | 9, kept and flagged |
| Home flag set but venue country differs from the home team | 988, kept (historical territories, flagged) |
| Shoot-out rows with no matching result | 1 |
| Shoot-out recorded although the listed score is not level | 37 (upstream records some scores differently); these rows are not used to fit the shoot-out model |

Leakage controls, each enforced by a test rather than by review:

- Rewriting one match's score leaves every feature row up to and including that match unchanged.
- Features for the first N matches are identical whether or not later matches exist.
- The model matrix is selected by registry name; outcome columns present in a frame change nothing.
- Folds are chronological and disjoint; the 2026 test fold was scored once, after selection.
- The pre-tournament bundle's last training match, calibration window and team state all precede 2026-06-11.

No random split is used anywhere. No hyper-parameter, blend or calibrator was chosen on test data.

## 5. Benchmark

Walk-forward: train from 1990, validate on the four years before each test window (early
stopping and calibration), test on the next four. Full tables: `BENCHMARK_V3.md`.

Mean log loss over four development folds (15,538 test matches):

| Model | Log loss |
|---|---|
| Class prior | 1.0488 |
| Elo, ordered logit | 0.8841 |
| Poisson | 0.8763 |
| XGBoost | 0.8760 |
| Poisson + Dixon–Coles | 0.8754 |
| Multinomial logit | 0.8751 |
| **Poisson-DC + XGBoost, equal weights (selected)** | **0.8736** |
| Poisson-DC + logit + XGBoost, equal weights | 0.8733 |

The two best are within the pre-set tie margin (0.001); the simpler was taken. Calibration
method, mean development log loss: none 0.8770, temperature 0.8774, sigmoid 0.8776, isotonic 0.9298.

Final test, never used for any decision — all 801 matches of 2026:

| | Log loss | Brier | RPS | Accuracy | ECE |
|---|---|---|---|---|---|
| Class prior | 1.0500 | 0.6333 | 0.2294 | 47.8% | 0.026 |
| Elo, ordered logit | 0.8814 | 0.5170 | 0.1739 | 60.2% | 0.032 |
| Selected model | 0.8733 | 0.5119 | 0.1723 | 60.9% | 0.034 |

## 6. What improved and what did not

**Improved**

- Against the model production serves (v1.0.0), on the 104 World Cup matches: log loss 0.849 vs
  0.984, accuracy 65.4% vs 54.8%. Paired difference −0.135, 95% interval [−0.208, −0.054].
  On the 28 matches v1.0.0 had not trained on: 0.695 vs 1.001, interval [−0.394, −0.217].
- Against the class prior on all of 2026: −0.177, interval [−0.209, −0.144].
- Predictions no longer depend on team order; the simulator follows the real bracket and rules;
  results are reproducible; an unvalidated model produces an error instead of a number.

**Did not improve, or cannot be claimed**

- **Not distinguishable from plain Elo on the 2026 test.** −0.008 log loss, interval
  [−0.016, +0.0004]. The gain over Elo is consistent across all four development folds
  (about 0.010) but it is small. Most of the predictive power here is the Elo rating.
- **Plain Elo does as well as V3 on the World Cup, at identical cutoffs.** Ratings frozen before
  the tournament: Elo 0.845, V3 0.838, difference −0.006 [−0.029, +0.016]. Ratings rolled
  forward: Elo 0.852, V3 0.849, difference −0.003 [−0.026, +0.019]. Plain Elo also beats v1.0.0
  by the same margin V3 does (−0.132 [−0.208, −0.048]). The improvement over production comes
  from the rating engine and the wider data, not from the blend on top of it.
- **Not better than the existing V2 frozen ledger on the World Cup.** That ledger scores 0.815
  log loss and 70.2% against V3's 0.838 and 66.3% (ratings frozen before the tournament).
  The difference, +0.024, has interval [−0.046, +0.102]: 104 matches cannot separate them.
  V2 is not the production default, and its team-strength inputs cannot be certified as
  pre-tournament (finding 8), but on this sample it is nominally ahead and I am not claiming otherwise.
- **Draws are never the top pick.** Draw recall is 0 for every strong candidate. The draw
  *probability* is reasonable (mean 22.9% on the 2026 test; 22.7% of all matches in the corpus are draws), but the argmax is never a draw.
- **Calibration on the World Cup sample looks loose** (ECE 0.144 on 104 matches against 0.034
  on 801). With 104 matches that is mostly noise, but it is not evidence of good calibration.
- Fitted blend weights, a three-model blend, isotonic and sigmoid calibration, and an XGBoost
  goals model were all tried and not adopted: none beat the simpler choice out of sample.

### Fairness of the comparison

| Model | Fitted on | Team state at prediction time | Pre-match only? |
|---|---|---|---|
| V3, plain Elo (frozen) | matches before 2026-06-11 | matches before 2026-06-11 | yes, enforced by tests |
| V3, plain Elo (rolling) | matches before 2026-06-11 | matches before each fixture | yes; one-step-ahead, the same regime as the walk-forward folds |
| V2.1.0 ledger | World Cups through 2022 | accumulators at end of 2022, plus team Elo / FIFA rank with no date or source | **cannot be verified** |
| v1.0.0 | a file ending 2026-06-30 | history cut before each fixture | **no** for 76 of the 104 matches: they are in its training file |

So the cutoffs are identical only between V3 and plain Elo. v1.0.0 has an in-sample advantage on
76 matches (and still loses); the V2 ledger has an older model cutoff and inputs of unknown date.
Other points checked:

- Every model is scored on the same 104 matches with the same outcome definition and the same
  metric code; differences are paired bootstraps.
- No team plays twice on one day in the 2026 test, so same-day ordering cannot leak a result
  into a feature (19 such team-days exist since 1990, out of 65,623).
- The rating parameters were tuned on the test windows of the first three development folds
  (2010–2021). Those folds are therefore mildly optimistic for every rating-based model alike,
  plain Elo included. The 2022–2025 fold and the 2026 test were not used for it.
- The 2026 fold was scored by the same script as the development folds each time the benchmark
  ran during development. Selection is programmatic and reads development folds only, but I
  cannot claim the 2026 numbers were seen exactly once.

## 7. Acceptance criteria and outcome

Set after the baselines were measured, before the final test was opened.

| Criterion | Outcome |
|---|---|
| Beats class prior and Elo on every development fold (log loss) | met, 4 of 4 |
| Final-test log loss no worse than the development mean plus 0.01 | met: 0.8733 vs 0.8736 |
| Better than the production model on common matches, interval excluding zero | met vs v1.0.0 |
| Exact order invariance; valid probabilities; champion probabilities sum to 1 | met (tested) |
| Replays the real 2026 tournament from its 104 results | met: all rounds, champion Spain |
| Leakage tests pass | met |
| No team special-cased | met: equal teams each get 1/48; modelling code names no country |
| Legacy path intact and switchable | met: `PREDICTION_ENGINE=legacy` |
| Better than every existing model | **not met** — see V2 ledger above |

Because the last criterion is not met and the gain over plain Elo is not established, **the
legacy engine remains the default**. V3 is an explicit opt-in (`PREDICTION_ENGINE=v3`). Nothing
has been committed, pushed or deployed.

## 9. Limitations

- **No player-level information.** No squads, injuries, suspensions, lineups, club form, market
  values or expected goals. None was available with a verifiable source, and none was invented.
- **Scores are after extra time.** The source does not separate 90-minute scores, so a match
  won in extra time is a win in training. Knockout simulation adds extra time on top, which
  slightly double-counts; the size of the effect was not measured.
- **Extra-time scoring is assumed**, at one third of the 90-minute rate. Not fitted.
- **Lot replaces fair-play points and FIFA ranking** when head-to-head and overall goal records
  cannot split teams. Neither is in the data.
- **Home advantage is one global value**, applied when a team plays in its own country.
  Co-hosting, altitude, travel and crowd composition are not modelled.
- **Custom groups are simulated at neutral venues.**
- **`confidence_score` is a data-sufficiency measure**, not a probability of being right.
- **The explanation covers the XGBoost half of the blend only**, and says so.
- **Same-day matches** are ordered by the source's row order; kick-off times are not available.
- **The database could not be reached**, so nothing was verified against production data, and
  the normal API start-up path (which requires the database) was not exercised. Endpoints were
  exercised in-process and over HTTP with the start-up check disabled.
